Для комплексной оценки спецификации v2.0 и её будущей реализации потребуется кросс-функциональная экспертиза, охватывающая аппаратный, сетевой, криптографический, программный и юридический уровни. Ниже — карта ролей и их зон ответственности.

---

1. Эксперт по встраиваемым системам и аппаратному обеспечению (Embedded Systems Engineer)

Зона ответственности: Верификация физической осуществимости и ресурсных бюджетов.
- Проверка ToH: Подтверждение совместимости ревизий Cudy WR3000S/TR3000 с OpenWrt (проверка серийных номеров, наличие отладочных портов, состояние загрузчика).
- Ресурсный аудит: Измерение реального потребления RAM (VmRSS) при пиковой нагрузке sing-box + urltest по 500+ узлам. Верификация, что GOMEMLIMIT=90MiB не вызывает OOM-killer при активных 1000+ соединениях.
- Износ NAND: Оценка циклов записи логов (проверка, что кольцевой буфер действительно работает в tmpfs, а не на флеш).
- Тепловой режим: Мониторинг температуры SoC MT7981B при отключённом flow offloading и нагрузке 300 Мбит/с (риск троттлинга в корпусе TR3000).

2. Специалист по сетевой безопасности и анализу трафика (Network Security / Traffic Analysis Expert)

Зона ответственности: Оценка эффективности маскировки и устойчивости к DPI.
- Анализ fingerprinting: Проверка, не выделяется ли трафик VLESS+Reality поведенческими паттернами (размеры пакетов, интервалы) при прохождении через ТСПУ.
- Валидация DPI-стратегий: Тестирование профилей nfqws (Zapret) на реальных провайдерах с разными типами DPI (активный/пассивный анализ, редиректы).
- Leak-тестирование: Проверка утечек DNS (включая DNS-over-HTTPS с резолвером 1.1.1.1 внутри туннеля), WebRTC, IPv6, а также утечек временных меток (NTP) при холодном старте.
- Kill Switch аудит: Попытка обхода блокировки при помощи альтернативных портов (проверка, что трафик действительно не уходит в clear net при падении туннеля).

3. Эксперт по OpenWrt/Embedded Linux (OpenWrt Architect)

Зона ответственности: Корректность системной интеграции и стабильность служб.
- Интеграция с procd: Проверка, что sing-box корректно стартует/останавливается, обрабатывает SIGHUP (перезагрузка конфига), не оставляет зомби-процессов.
- Конфликты пакетов: Анализ совместимости travelmate, mwan3 (если используется), firewall4 и кастомных скриптов hotplug (99-singbox-wan-switch).
- UCI-конфигурация: Верификация, что все изменения (/etc/config/network, firewall) сохраняются после sysupgrade и не конфликтуют с дефолтными скриптами
  OpenWrt.
- Производительность ядра: Оценка влияния отключения flow_offloading на общую пропускную способность NAT (не только VPN).

4. Разработчик/Инженер по протоколам sing-box / Xray (Core Client Developer)                                                                            
Зона ответственности: Валидация конфигурации sing-box и логики маршрутизации.
- Schema-валидация: Проверка config.json на соответствие версии sing-box 1.10/1.11 (валидность полей default_mark, address_Fallback, idle_timeout в указверсии).
- Логика urltest: Оценка корректности алгоритма выбора узла (интервал 2m, толерантность 120ms) — не приведёт ли это к «флаппингу» (постоянному переключению между узлами) при нестабильной сети.
- TPROXY/TUN: Проверка корректности настройки tun0 (MTU 1400, auto_redirect) и отсутствия маршрутных петель при работе с .srs-правилами.                Clash API: Проверка безопасности локального API (10.10.1.1:909орректность работы hotplug-скриптов с API (DELETE /connections,GET /group/delay).                                                                                                                                    
5. Инженер по качеству ПО (QA/Test Automation Engineer)                                                                                                 
Зона ответственности: Полнота и воспроизводимость приёмочных испытаний (ATP).
- Покрытие тестами: Анализ чек-листа T1–T10 на предмет «дыр» (например, отсутствие теста на одновременное подключение 50+ клиентов, отсутствие теста на деградацию скорости при 90% загрузке RAM).
- Автоматизация ATP: Оценка возможности автоматизации проверок (написание скриптов для T1, T2, T5, T10), чтобы ATP можно было прогонять после каждого обновления прошивки.
- Тестирование отказоустойчивости: Проверка механизма rollback (симуляция зависания sing-box, проверка, что lock-файл срабатывает и восстанавливает конфиг через 300 сек).                                                                                                                                        
6. Специалист по информационной безопасности и криптографии (Security Auditor / Cryptographer)                                                           
Зона ответственности: Криптографическая стойкость и отсутствие уязвимостей в цепочке доверия.                                                            Аудит ключей: Проверка, что sub2sing.py не логирует приватные то передача конфига на роутер происходит по защищённому каналу(SCP/SSH с ключами, а не паролем).
- TLS-гигиена: Проверка, что DoH-серверы (77.88.8.8, 1.1.1.1) используются корректно, без downgrade до HTTP или небезопасных шифров.                     Секреты в конфиге: Анализ /etc/sing-box/config.json на предметых (если подписка содержит пароли, они не должны быть доступнывсем пользователям роутера — права доступа 600).

7. Эксперт по сетям операторов связи и мобильной связи (Mobile Network Specialist)                                                                       
Зона ответственности: Работа в условиях мобильных сетей и публичных Wi-Fi.                                                                               RNDIS/NCM стабильность: Тестирование USB-тетеринга с разными A телефоны отключают USB-интерфейс при блокировке экрана —требуется проверка usb0 keepalive).                                                                                                                    Captive Portal bypass: Проверка, что travelmate корректно обраалов (HSTS preload) и что скрипт crne-portal-hook.sh не оставляет роутер в «открытом» состоянии после прохождения портала.
- LTS-мобильные узлы: Верификация, что серверы, помеченные как «mobile-only», действительно доступны только с IP мобильных операторов (проверка с разных SIM-карт).

8. Юрист по IT и телекоммуникационному праву (Legal Counsel — IT/Telecom)

Зона ответственности: Соответствие законодательству и оценка пра
- Соответствие 149-ФЗ и 276-ФЗ: Проверка, что архитектура не подпадает под определение «средства обхода блокировок» в корпоративном смысле (для личного
  использования допустимо, но нет ли признаков «предоставления у
- Публичная оферта: Если проект будет публичным (open source), оценка рисков распространения инструкций по обходу блокировок (ст. 13.53 КоАП РФ — штрафы для
  юрлиц до 700 тыс. руб., для граждан — предупреждение/штраф).
- Защита персональных данных: Оценка, что логи (даже в RAM) не содержат персональных данных третьих лиц (GDPR, 152-ФЗ), если роутер используется в гостевом режиме.

9. Специалист по DevOps/SRE для встраиваемых систем (Embedded DevOps/SRE)

Зона ответственности: Жизненный цикл, мониторинг и обновления.
- CI/CD для конфигов: Оценка процесса сборки config.json на ПК (sub2sing.py) — есть ли версионирование, проверка синтаксиса перед отправкой (CI-пайплайн),
  автоматический откат при ошибке.
- Мониторинг эксплуатации: Разработка метрик (доступность urltest, скорость, uptime узлов) и алертинга (Telegram-бот или SNMP), чтобы пользователь узнавал о
  деградации сети до того, как «пропал интернет».
- Backup/Restore: Проверка процедуры sysupgrade -b — восстанавливается ли конфигурация полностью, включая права доступа на файлы и симлинки.
